# Resolution Lifecycle Governance (MPF-RES-003)

## 1. Purpose
This document defines the **governed lifecycle** for unresolved mathematical structures. It establishes the legal transitions between states—such as repair, stress testing, and permanent preservation—ensuring that unresolvedness is managed as an evolving admissibility state rather than a binary solved/unsolved defect.

## 2. Core Question
> **How does an unresolved structure change governance state over time?**

The lifecycle answer is that it moves toward a state of **stabilized classification**, whether that state is a repaired derivation or a formally preserved open boundary.

## 3. Lifecycle States

- **under_repair**: Active work is ongoing to complete artifacts or result traces.
- **under_operationalization**: Symbolic scaffolds are being implemented into testable code.
- **under_stress_test**: Recursive stability is being probed via adversarial simulation.
- **under_deception_analysis**: Probing for false stability grooves or hidden instabilities.
- **bounded_preserved**: Structure is verified locally but blocked from global extension.
- **irreducible_preserved**: Structure represents a necessary permanent open feature.
- **quarantined**: Isolated due to non-repairable scope breaches or extreme drift.
- **repair_failed**: Attempted repair did not achieve stabilization.
- **permanently_open**: Final state for irreducible features or unresolvable gaps.

## 4. Critical Transitions

### 4.1 Metastable to Irreducible
- **Condition**: Stress testing shows that instability is a fundamental property of the local topology rather than a numerical artifact.
- **Outcome**: Preserved as `irreducible_preserved` within the failure geometry map.

### 4.2 Symbolic to Operational
- **Condition**: Implementation of a scaffold passes initial implementation checks.
- **Outcome**: Transitions to `under_repair` or `under_stress_test`.

### 4.3 Deceptive to Quarantine
- **Condition**: False stability trap is empirically confirmed.
- **Outcome**: Immediate isolation to prevent proof contamination.

### 4.4 Repair Failure to Permanently Open
- **Condition**: Exhaustion of repair tracks without stabilization.
- **Outcome**: Classification as a fundamental incompleteness constraint.

## 5. Important Rules
- **Non-Binary Validity**: Failure to achieve final "closure" (proof) does not imply the structure is invalid or meaningless, provided its local boundaries remain verified.
- **Traceability Mandate**: Every transition must record the evidentiary trigger (e.g., a specific simulation run or audit failure).
