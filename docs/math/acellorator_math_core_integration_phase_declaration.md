# Acellorator Math-Core Integration Phase Declaration (MPF-ACELL-INTEG)

## Purpose
This document declares the **Mono-Process math core** as a stabilized interpretive/governance module within Acellorator. It does **not** elevate theorem status, close ontology, or authorize physics claims.

## Layering Model

1. **Math Core (Authority for Meaning)**
   - Canonical operator/law/failure registries: `registry/math/`
   - Human-readable codex and restricted theorem program: `docs/math/`
   - Validation program outputs (records only): `validation/results/`

2. **Simulation Ecosystem (Bounded Evidence Only)**
   - Engines and analysis tools: `tools/`
   - Orchestration and evidence packet emission: `scripts/multi_sim_runner.py`
   - Recoverable artifacts: `outputs/`

3. **Claims (Governed, Evidence-Bound)**
   - Claim registry and status ladder: `registry/claim_registry.json`
   - Claim-scope bindings (required phrasing, evidence types): `registry/claim_scope_binding_registry.json`

## Hard Constraints (Non-Negotiable)
- No claim that simulations prove the framework.
- No physics derivation language.
- No QM/GR unification language.
- Every simulation-facing statement must begin with: **"Within these models..."**.
- Python prototypes remain reference baselines.
- C++ engines require Python↔C++ equivalence evidence before rigor endorsement.
- Run artifacts must be recoverable via configs, seeds, outputs, and validation records.
- Math-core relation integrity must not be weakened by simulation terminology.

## Status
Integration phase declarations are governance scaffolds. They are not proof artifacts.
