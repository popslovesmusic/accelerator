# Projection vs. Primitive Distinction Standard

## 1. Purpose
This document defines the formal criteria for distinguishing the true primitives of the Mono-Process Framework from the vast set of derived, stabilized process projections. This standard is enforced by the `validate_process_first_ontology.py` script.

## 2. The Primitives
The framework has only **one** primitive: the inseparable process relation itself.
$$ (\mathcal{E} 
e 0) \Leftrightarrow_R \delta(\mathcal{E} > 0) $$
The core "aspects" of this relation—Distinction (ℰ≠0), Continuation (δ(ℰ>0)), and Residue-Binding (⇔_R)—are the axiomatic components.

## 3. Criteria for a Stabilized Projection
An object or structure is a **stabilized projection** if it meets the following criteria:
1.  **Derivability:** It can be formally derived from the recursive application of the core process expression.
2.  **Meta-Stability:** It only exists within a bounded **Validity Window** ($V(M_U)$) and is subject to dissolution or transition when process conditions change. It is not eternal or universal.
3.  **Non-Substantiality:** It is not a "substance" or "container" but is a pattern of process activity. For example, a "basin" is a pattern of recurrent continuation, not a literal bowl.
4.  **Contingency:** Its existence depends on the persistence of the underlying process dynamics that create it. If the process stops, the projection vanishes.

## 4. Audit Checklist
When evaluating a new concept, ask:
- Can this object exist without the core process relation? (If yes, it is forbidden substance reification).
- Does it have a finite lifespan or is it claimed to be permanent? (If permanent, it is forbidden reification).
- Is it a "thing" or is it a "pattern of doing"? (If a thing, it is forbidden reification).
