# Onboarding: `5_03_26 unity`

This folder is being treated as an in-progress “book” made from several working documents (Markdown/TXT/DOCX). It is **not yet a finished manuscript**. The goal is to make it readable, navigable, and honest about its current maturity.

## What this is (and isn’t)

- This is a **working compilation** of foundational notes and technical papers around “phase packets,” “two-threshold” dynamics, hysteresis, and related mapping language.
- It is **not** a finalized theory text, and it is **not** intended as a claim of universal physical truth.
- Many sections are written in a strong, declarative style; treat those as **authorial intent / hypotheses + model results**, not as settled fact.

## What to expect: tone, vocabulary, and precision

- **Vocabulary:** Terms like *epsilon*, *residue*, *rho*, *coupling/kappa*, *admissibility*, *phase packet*, and *hysteresis* are used with specific internal meanings that may differ from standard physics usage.
- **Symbols:** Several documents use math symbols and shorthand that are still being stabilized (e.g., δ, κ, ⟿). Some files also contain encoding artifacts (e.g., characters that display oddly).
- **Precision:** Some sections are precise (data paths, model classes, seeds, falsification vectors). Others are conceptual scaffolding that still needs careful definitions and “operationalization.”

## Evidence posture (honest constraints)

Where these documents are strongest:

- When they report **model outputs** with explicit runs, seeds, model classes, and recoverable output paths.
- When they separate **operational definitions** (what is measured) from **interpretations** (what it might mean).

Where they are weaker or incomplete (and should be read cautiously):

- When a term is used as if it were universally defined, but it is only defined inside this internal framework.
- When a conceptual bridge is suggested (e.g., “quantum-like” behavior) without a carefully bounded operational definition and negative controls.
- When cross-model agreement is asserted but not clearly tied to independent mechanism classes and reproducible artifacts.

If you are looking for “final answers,” this folder is not yet that. It is closer to a research notebook that is being pushed toward a governed, testable format.

## Contributing / editing guidance (gentle defaults)

To keep the compilation honest and easy to evolve:

- Prefer **adding wrapper chapters**, summaries, and placeholders rather than rewriting source files.
- When introducing a new term, try to give:
  - an operational role (what it does),
  - an observable or measurement proxy,
  - and a falsification condition (what would show it is wrong).
- When making a stronger claim, prefer upgrading the evidence trail first (reproducible runs, cross-model checks, negative controls) before upgrading the tone.
