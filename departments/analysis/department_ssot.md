# Analysis Department Single Source of Truth (SSOT)

This document is the local SSOT for the Analysis Department.

It governs program-state assessment, dependency analysis, priority ranking, and recommendation synthesis from governed evidence.

The Analysis Department is subordinate to the global core, global governance, and the Mathematics Department. It does not define RT/Core, primitive operators, formal admissibility, formal residue, theorem status, or executable authority. It consumes live ledgers, the Work Reduction Framework, the Master Work Index, and the department relationship registry, then outputs recommendations only.

---

## Department Charter

The Analysis Department exists to transform governed state into governed recommendations.

Boundary rule:

Governed registries define executable state. Analysis converts that state into ordered recommendations without modifying source authority.

Methodological rule:

No analysis recommendation may be issued without citing the live artifact set it was derived from.

---

## Scope and Boundaries

### In Scope
- program-state assessment,
- dependency analysis,
- critical-path identification,
- priority ranking,
- governance-gap detection,
- recommendation synthesis,
- reproducible state summaries.

### Out of Scope
- modifying authoritative registries,
- executing or closing work,
- promoting theorem, proof, lemma, or governance state,
- inventing unmet dependencies,
- replacing source ledgers with analytic projections.

### Claim Ceiling
Unless separately validated, Analysis Department outputs are capped at:
- `C1_model_relative` for recommendation scaffolds,
- `C3_structural_comparison` for comparative program-state assessments.

No analysis output may be treated as promotion authority.

## Analysis Framework

All Analysis Department outputs must distinguish:
1. source artifact set,
2. normalization or dependency rule,
3. recommendation class,
4. confidence or support level.

Interpretive boilerplate:

`Within the Analysis Department interpretation...`

### Ordering Rule

Recommendations are ordered by direct unlock value, then by reduction of normalization gaps, then by breadth of downstream impact.

### Reproducibility Rule

Given the same governed state, the Analysis Department should produce the same ordered recommendation set.
